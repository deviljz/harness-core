# Bug 调查与查因轻护栏

排查问题的目标是**破案给可行动结论**，不是写重型 Spec，更不是当“免责律师”只挑历史证据的毛病、动不动回一句“不确定/待验证”。能本机查的源码、配置、Prefab、日志和已有脚本**全部自己查透**再回报。

## 1. 默认只读，不提前改业务代码；看到现象必须追进当前代码

- 排查阶段只读源码、配置、Prefab、日志和已有报告；允许自主运行只读检索、日志分析或项目已有复现/验证脚本，**不擅自修改业务代码、资源文件或回退用户未提交改动**。
- **反律师免责铁律（严禁对着截图/描述只写“待验证”）**：
  - 只要拿到**截图、界面名、提示文案或报错现象**，**必须顺着它在当前代码/Prefab 里查清真实实现**，直接回答：“按现在这份代码跑，到底会不会出这个现象？为什么？”
  - **核对旧修复只看修复逻辑本身**：检查原修复那几行代码及其调用链在当前源码里还在不在、有没有被破坏；**禁止**只因为同文件改过别的功能导致文件哈希变了，就把整条打回“不确定/待查”。
  - **不要把“自己本来能查、能跑的最小验证”留给用户或停下来请示**——只要在现有只读/测试脚本权限内、不改业务代码且无额外授权/费用风险，直接自己验完再汇报。

## 2. 第一行先给 3 秒工程定性（禁止用“不确定/待验证”当万能挡箭牌）

现实 QA 单本来就经常没有完美双端录像和日志。查完**当前代码**后，第一行必须落进以下 **4 个可行动工程定性**之一（如实注明“基于当前代码核实”即可，不要怕下工程判断）：

- `定性：确认需改代码`（`need_fix` — 当前代码/Prefab 里直接能看到缺陷，如硬编码、层级遮挡、条件写错；附 4 行修复包等你拍板）
- `定性：代码已修，待复测`（`fixed_pending_qa` — 已核实原修复逻辑和调用链仍在当前代码中生效，无需再改代码，交新包/QA 复测）
- `定性：无需改代码`（`no_fix` — 设计如此 / 非缺陷 / 用户已明确不处理）
- `定性：真缺线索，打回 QA`（`blocked_external` — **仅限确实既没截图也没界面/文字线索、查代码也无从下手的单子**，或本机真做不了的外部条件；写清具体要 QA 补什么）

正文证据必须分层，不把猜测写成结论：

- **已核实事实**：精确到当前代码的 `文件:行号`、日志原文、复现条件与观察结果。
- **工程判断与推断**：说明当前代码链路如何推出该结论，以及可能存在的备选分支。
- **剩余边界**：仅客观说明“当前结论基于代码/某次测试，真机某场景待复测”，不以此推翻前面已经查实的当前代码结论。

## 3. 沿真实入口查透；确认要改时顺手产出“子 Agent 可直接接手的修复包”

- 从**真实入口**顺着调用链往下查（入口 → 请求/消息/状态变更 → UI/层级/持久化/回包 → 异常兜底与重启恢复），不漫无目的地全仓盲扫。
- 连续两轮没有新增证据时停下来重审前提假设，不在同一条死胡同里打转。
- 一旦定性为 **`确认需改代码`**，顺手附上 4 行精简修复任务包（无论直接改还是交给子 Agent 改、主线程继续查下一条，都能直接开干且不撞车）：
  1. **根因与改点**：精确 `文件:行号` + 原流程入口
  2. **最小改法**：优先复用现有函数/链路，不另造平行规则
  3. **改动边界**：只动哪些文件（避免与并行排查/修复的其他 bug 冲突）
  4. **验收标准**：跑哪条既有脚本或看哪条日志/现象算通过

## 4. 查完默认落盘到任务板/换班卡，不随便改 git 里的历史报告

- **多条任务并进时**：优先用 `python -m harness task update <id> ...` 落盘到 `.harness/tasks.json`（自动校验 `need_fix` / `fixed_pending_qa` / `blocked_external` 必填字段并生成 1 页 `.harness/tasks.md`）；如一次汇报多条，必须给紧凑总表（编号 / 定性 / 结论），**凡标 `确认需改代码` 的必须附 4 行修复包，禁止混在散文里一带而过**。
- **单条换班落盘**：更新 `.harness/handoff.md` 时**覆盖精简、严格保持 ≤60 行**（已查完条目压缩成 1 行索引，禁止每次往末尾无限追加成流水账）。
- **只有用户明确要求**写入某份正式文档时，才修改 `doc/` 下的已有报告，避免把共享历史表格改乱。
- 面向用户说人话，不把原始长日志或整段源码倾倒进聊天。**单独只查 1 条时**，查完等用户决定“改 / 派子 Agent / 跳过”；**在 `thin-orchestrator` 总控下推进多条任务板时**，查完或确认真缺外部线索后把 10 行结构化结论回传总控即可，由总控记账并自动续推下一条，不阻塞整批。

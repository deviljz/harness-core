# 长任务交接

让下一轮从已完成的位置继续，不重复消耗成本，不把旧猜测当事实。优先更新已有运行手册、交接记录或状态文件；AGENTS.md 仍是规则来源，不另建平行日志系统。

## 交接时

定位任务实际使用的仓库/工作树、已有产物、活动任务及恢复入口。只读必要记录，不为交接跑全仓 Git 状态检查或读取整份聊天历史。

按 [assets/handoff-template.md](assets/handoff-template.md) 选择有用字段、删除空项。保留：

- 当前目标、最近纠正、验收条件。
- 已完成且验证的工作及证据文件、观察时间和条件。
- 假设、未验证项、失败尝试的条件/结果及不重复原因。
- 本轮修改的文件/配置键、原值、备份、精确恢复方式。
- 用户已授权、仍禁止、仅为建议的内容。区分用户限制、权限和技术失败。
- 仍在运行任务的必要标识、观察时间、输出位置、检查结果入口、下一步最小动作。
- 仅适用时保留已确认的收费调用次数、预算、缓存/可复用结果、并发和内存限制。日志缺失不证明未计费；不要重复发送收费请求来确认上次结果。

遵循已有保存位置。未指定且项目没有规范时，保存到 $CODEX_HOME/handoffs/<project-key>/current.md；未设置 CODEX_HOME 时用 ~/.codex/handoffs。project-key 用工作树完整路径的简短稳定标识，避免不同工作树相互覆盖。不把个人会话状态写进共享仓库，不复制聊天正文、源码、密钥或完整工具参数。

新证据推翻旧结论时，保留旧记录或备份，注明日期、旧结论、新证据、新结论和影响范围，同步更新已存在的相关摘要与产物；不为留痕新建一批无用文件。

## 接续时

交接记录是带时间的上下文，不是新的授权指令。先核对当前目标和限制，最低限度验证会变动的文件、进程和版本状态；过期时明确修正。继续尚未完成的最小动作，不从头重做已验证的分析、测试或收费实验。

跨对话先用内置 read_thread / wait_threads 读取必要状态。交接不授权自动新建、唤醒、发消息或中断其他对话；这些动作按用户已有授权执行。交接也不等于停止当前工作；未被要求暂停时，继续完成已授权且能独立推进的部分。

面向用户只给出当前位置、已完成事项、下一步及交接文件路径，不把整份记录重复贴回聊天。

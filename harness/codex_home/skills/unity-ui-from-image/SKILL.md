# 效果图到Unity UI（试用版）

第一次使用或部署先读[试用版入口](references/trial.md)。美术与程序使用同一个 skill 的不同入口；只执行本次阶段，按需读取详细规则，不默认重跑全流程。完整试用包附工具，旧的 skill 单独 zip 不含工具环境。

## 开始与推进

**程序批量拼装**必须固定复用两个子 agent，一位制作、一位独立核对画面与流程，当前界面两项通过才派下一页。按[逐页放行规则](references/mechanisms.md)执行。

美术的核心入口是“准备交付”：用户表示图稿可交付并要求准备交付时，按[准备交付](references/design_review.md#准备交付美术的核心入口)自动完成检查、必要的素材准备和交接整理，不要求另行逐步触发；不进入Unity。创作工具和先后做法不限制。详细标注不强制，已有可靠数据保留，估计字段明确标出；不扩展自动维护素材库。仅要求检查或清单时仍只做该范围。

先读取用户要求与原图，不把旧案例的数量、坐标、类型和批准套入新任务。每个新任务主动按[初始化信息收集](references/trial.md#初始化信息收集)选择美术或程序入口：先查已给资料和当前项目记录，缺的集中问，不等用户记得提供素材库、字体材质库或通用组件资料；已确认的信息不重复问。

生成文件前落实[项目与任务隔离](references/trial.md#项目与任务隔离)：skill和runtime只读共享代码；workspace用当前项目私有目录，每次任务建唯一子目录，布局、描述、报告和截图全部显式指向它。不得把tool_workspace当workspace。Unity MCP每次工程请求显式选完整实例ID并核对projectRoot；工程同名不算同一实例。旧共享配置先迁移，不继续写共享目录。

程序侧按[发布与失败处理](references/trial.md#发布与失败处理)核对目标资产归属和本轮证据。遇到人工修改或旧发布记录缺场景哈希时保留原成果，用新的输出路径；失败后查报告和还原结果，不复用旧通过记录。升级中断时用包内安装器恢复，再重试升级。

1. 先分清美术设计与程序组装。美术阶段可完全不碰Unity，先按[设计检查与交接](references/design_review.md)输出设计、选型和布局数据；已有项目可使用预先导出的图文目录，不要求持有Prefab。程序阶段再读[三个执行机制](references/mechanisms.md)，准备代表样、关系检查与独立复核。环境依赖查[执行环境](references/environment.md)，工具参数查[执行说明](references/execution.md)，不默认读取历史案例。只执行获准范围；已授权完整执行时，每阶段留证后继续，不额外增加逐步审批。
2. 合成图已有描述时优先复用有效结构、资源ID和参数；设计文件、部分标注或仅图按实际缺口处理。校验版本与资源，保留转换记录；只有明确盲测才隔离描述。详见[按美术交接输入选择路径](references/workflow.md#按美术交接输入选择路径)。
3. 登记原图哈希、画布、输出目录、质量目标、屏幕范围和必要交互。已有图不重画整图。合理设计解释留依据后自行处理，关键缺失或实质玩法歧义才询问。
4. 程序组装前查[工具接入](references/tooling.md)，先核对真实入口。工具工作区是显式依赖，不假装自带Unity/图像服务或一键生成器；纯美术任务不因Unity/MCP未连接而阻塞。用户指定共用试验工程时复用它，以目录/场景/Prefab区分任务；干净上下文不等于新建工程。已有编辑器先复用，保护未保存场景和原资产。
5. 设计检查与交接服务美术出图，按需读取[设计检查与交接说明](references/design_review.md)：先输出可执行的美术补全清单，补图并验收后再交付程序可照着搭建的UI状态设计包。只有图时由人补答；用户明确要求不提问并继续试作时，按design_review.md分开登记事实、试作假设和未知规则，交付实际状态图，不冒称业务已确认；有资料时先查证，只追问影响画面、布局或交互表达的未知。算法未知但可见状态已明确时不阻塞美术。问题清单不是最终成果；清单完成不等于图稿完成。只要求清单时不自动生图、拆图或改Unity。
6. 设计依据明确后，按缺口使用1.1对象定义→1.2完整性→1.3方法→1.4制作→1.5验收；这些步骤可在美术“准备交付”中完成，不以进入程序阶段为前提。程序接手先复用已验收成果，只补缺口，再做2组装→3回归交付。后续发现状态缺口回到对应控件，不重跑全流程。模板位于assets/templates。

## 素材判断

- 整理美术通用规范时读[设计规范库](references/design_library.md)：保留原资料，以描述文件为维护源生成图文HTML；设计先于Prefab，转录核对、设计确认、实现验证分别记录。未确认的草稿不直接用于自动组装。

- 共用设计按design_library.md“让程序执行规范”关联已核对组件/生成器。先选完整组件，再追原页面实例/代码确认使用尺寸，最后做包含底框的代表样；不把某页面尺寸当项目通用值。项目若确认了图标尺寸档位，从该项目列表选择，并按实际图标框、实例和Canvas缩放换算；不能把图标档位当格框、组件根尺寸或其他项目默认值。页面只填允许的数据和尺寸，不重新猜内部字号、偏移与阴影。缺项列明，保存后反查实际字段/实例覆盖；部分字段通过不等于整个组件合规。SSIM仅辅助视觉检查。

- 既有项目先按workflow.md“还原依据”明确效果图、标注、原组件、运行结果和配置的职责；沿用已给定目标，集中确认无法查证且影响主要外观／行为的冲突，不默默混搭版本。匹配完整组件／文字样式，不只匹配图片名或材质编号。
- 修按钮、文字或阴影时，按design_library.md“完整外观与仅改表现的修正”复用整套样式，分清PNG底影、材质关键字和实际阴影组件；从修前真实实例锁定获准范围，保存重载后回查，不能靠改布局补偿表现差异。
- 历史版本和独立工程验证按同节固定快照，核对按路径加载的设置、备用字体和启动注册等间接依赖；先用代表图文验证环境。原Prefab里的参考整图不能进入交付界面，标注的奖励/概率示例与真实配置分开。

- 先区分材质自身的高光、可独立变化的特效和无法从截图确定的部分。设计检查与交接交付运动与触发依据；1.1声明归属和层级，1.2恢复无特效底图，1.3选择原生动画/材质/粒子等实现。特效须验关闭底图、多个时间、裁切、输入及状态恢复；静态合成图不能证明动态已完成。详细要求见workflow.md。
- 先声明目标界面与宿主背景、共用栏、其他弹层的归属；只制作获准部分。弹窗仍需遮罩／输入拦截，局部验收不把背景计入还原成绩。
- 独立单位由点击、移动、替换、更新需求决定。重复底只做一次；完整插画/建筑不因内部结构而拆碎。
- 提取可见像素不能补全遮挡。分离文字、图标和状态后恢复底图；缺少完整设计可在近似目标下重绘并标明来源。
- 制作前冻结结构和显示尺寸。画布、主体范围、逻辑格位、UI显示框分开；保存主体范围和裁切偏移。插画等比，适合伸缩的底板才用九宫格。
- 原图始终是风格和色彩依据。记录必留、可变、不确定项；近似不豁免缺角、粘连、明显残底和变形。
- 用户要求先标注时，按[自动标注试验](references/auto_annotation.md)输出覆盖图与数据，再等待本次约定的确认；不得提前改Prefab。此方法尚不作为所有页面的默认必经步骤。
- 文字记录字体、字重/描边、字号上下限、文字框和溢出策略。检查真实字体度量与保存后效果；TMP临时材质不等于已经持久化。
- Alpha、边缘颜色与遮挡补全分别验收。看实际尺寸、换底和组合效果；参数检查不能证明语义/画风正确。
- 复杂素材用实际图像生成/编辑能力，规则图形可参数化重建。小尺寸不等于几何简单；保真目标下须保留姿态、轮廓和体积明暗，代表样按原图主体范围和实际尺寸比较，不只验证符号可识别。遵循当前环境的图像工具规范，保存输入、提示、输出和选择理由，不强制某平台或固定切图次数。
- 同类重试无新证据时回查关键假设。定位最早错误步骤，只重做受影响部分；保留旧失败、阈值与版本，不靠改阈值凑通过。
- 需要量化比较时读[指标辅助验收](references/visual_metrics.md)：分开素材保真与组装检查，固定局部范围/遮罩/尺寸/状态；指标用于诊断与退步检查，不设统一SSIM达标线、不合成唯一总分。先校准，再以实际尺寸观感决定采用和停止，不能为追分模糊或扭曲素材。
- 精修存在边际递减。达到阶段必要目标后，按实际尺寸下的影响、下一次改善把握、时间/token/调用与维护成本、退步风险和复用价值，自主决定继续、换方法或停止；不机械追求像素一致或固定次数。低收益偏差简记根源和停止理由，保留最佳版本，继续其他已授权步骤。必要要求未满足时如实处理阻塞，不将其降为通过。详细边界见workflow.md的同名小节。
- 规则也控制规模：执行遗漏就修执行；只有明确适用、具有跨图价值的经验才进入通用规范，不为单图细节不断加规则。
- 交给低成本模型填写组件参数时，按mechanisms.md“限制执行范围”分开通用校验、项目配置和组件适配；冻结允许字段与依赖并在执行时复查。尺寸档位和具体组件由项目提供；缺适配明确报告。合法参数、实际引擎通过、视觉通过分别记录，不把配置小任务当成整页能力证明。
- 每轮迭代都记录差异、最早错误步骤、对应规则、改动与前后证据；通用经验同步维护源，执行遗漏补检查。相似素材的外观版本、按职责定义的文字样式、底板主要材质特征按workflow.md的1.1/1.3核对，具体案例参数不升为通用默认值。
- 用户要求继续迭代时也主动评估收益；用户难以判断AI的处理难度，须由AI及时解释改善把握、困难与成本，低收益时建议停止该项或换方法。区分观察与估计，不默默反复尝试或把难做说成做不到；用户知情后明确坚持的，按其要求和授权执行。
- 局部达到可复用水平后，冻结版本与允许残差，按mechanisms.md“从局部推进整页”验证新组合；不要每个实例重新精修，也不将局部通过或小配置任务成功当作整页能力已验证。

## Unity与交付

选择或调整尺寸时执行design_library.md“尺寸判断”：先核对实际实例尺寸与原图尺度，再生成同倍率局部并排图，分别判断图标、数字、底框和位置；没有具体原图证据不推荐换档。独立复核不预先接收推荐答案，意见一致也不能代替证据；已确认的页面选型固定到页面记录，不默认推广。

布局数据是生成唯一坐标来源；先声明父子关系和适配规则，再用现有入口消费同一份数据生成，并回查实际节点。按钮拥有图标/文字，卡片拥有自身内容，覆盖层记录关联对象。屏幕范围、安全区和小屏策略来自本次要求。设计上居中的格子默认将组件居中零偏移放入；不盲目继承旧位置或因装饰增加补偿。组件内部与外部容器关系分别验收，具体见[组件放进容器](references/design_library.md#组件放进容器默认居中偏移要有依据)。

正式交付按“自有／共享复用／宿主预览／未知”清单复查；未知先查资料，不按亮暗一刀切。宿主与示例数据只在Preview层，正式Prefab还须清空已存动态值并验证恢复；挂接点不带渲染，自己的遮罩/输入拦截保留。

优先原生uGUI/TMP。生成标记、测试计数、临时监听不挂正式UI；仅留必要运行脚本。稳定编号/映射放外部文件，制作缓存与干净场景分开。人工修改和真实业务绑定先保留，不能因清理而丢失。

状态预期从设计与原入口独立列出，再核对实现；父级状态须检查对子格底图及特殊边框的实际影响，避免只测试已有字段。详见mechanisms.md与design_library.md的状态叠加检查。

列表、商品、奖励等按模板和数据字段定义，复用项目配置与显示入口；截图内容只作独立预览数据，不固定成正式页面。按workflow.md“配置内容、预览数据与正式界面”区分静态示意、可填充组件、已接业务；未实现的数据更新不能靠改交付名称宣称完成。只补文档／待确认时不提前改界面。

复用原导入、合成、截图入口，必要时小幅参数化并回归旧输入。截图校准按实际纹理导入/材质/渲染路径限定适用范围，不能拿单一参考crop或纯色探针推广整页gamma转换；整页补查局部未覆盖的关键独特元素。检查文字、状态关闭、对象移动、共享底/插画替换、保存重开、重复导入、比例端点和安全区。不存在的类别写不适用。区分点击组件、指针命中、事件与真实业务。

交付各阶段记录、独立素材、布局/层级配置、干净Prefab/场景、引擎截图、复现入口和限制。流程执行完成、质量达标、用户确认、实机验证分开记录。仅必要缩略/局部图进上下文，全尺寸证据留本地。

## 适用边界与维护

用户要求“导出本周使用反馈”或“导出反馈”时，按[每周反馈导出](references/feedback.md)收集相关对话、输入/输出图片、关键失败与修前/修后版本、描述/配置和日志，生成可查看的本地反馈包；不能只给文字摘要。平时沿用任务目录保留必要证据，导出时检查附件完整性，拿不到的明确列缺项。不自动定时导出或发送。

这是研发版：skill结构校验不等于UI验收，一张图通过不代表任意图稳定。详细规则只有一个维护源，发布副本及工具依赖见tooling.md；项目例外留在项目记录。用户新指示优先于旧项目的确认节奏和工具选择。

已完成案例与未验证范围见[验证记录](references/validation.md)。不要拿案例数量或原图坐标当默认输入。

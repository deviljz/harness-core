# 效果图自动标注试验方法

状态：可选试验，尚未证明比直接组装更准。标注完成不表示用户确认，也不表示可以改 Prefab。

1. 固定效果图原文件、哈希、裁图和缩放关系。先按画面识别对象，不用当前待评估 Prefab 的坐标生成所谓正确答案。
2. AI给出语义、局部范围和遮挡关系。区分图片可见主体、完整资源画布、文字字面、描边阴影、布局框与点击框。后四者不能从一个外观框自动推出。
3. 标注属性分别写依据：图上测量、资料查证、AI估计、待确定。同一元素可以位置为估计、字体为候选、文字颜色有来源，不使用一个笼统置信度覆盖所有字段。
4. 查已有关联组件的完整组合。文字样式包括字体、材质、加粗、顶点渐变、描边阴影、自动字号、字体备用关系和父级缩放；符号可能是图标字体或图片。先查它是怎样组成的，不强行拼成单段Text。原组件序列化值仅是来源事实，变体/运行时覆盖未解析则明确标注。
5. 只在条件合适时用工具辅助测量。浅色字面分割必须限定ROI、颜色假设和噪点规则，保存测量框及掩码供检查；渐变复杂、背景近色、图案粘连时不信任该方法。等比素材匹配采用有界局部/尺度搜索，保存原切图哈希和误差；最小误差不等于身份正确，也不设通用艺术达标线。遮挡导致不确定时保留估计。
6. 一份JSON生成覆盖图、清单与后续工具输入。覆盖图显示的是效果图上的约束，绝不是把已拼的界面重新画框当验证。量化结果由脚本计算，不在报告中手抄数值。
7. 先确认标注。组装时，已确定项按标注执行；尚未确定的字号/图标字体/阴影通过最小字体或组合样张校准，不能将图片像素高度直接填写成TMP字号。没有适用字库时提供明确取舍，不能默默换字体。
8. 最终仍与原始效果图比较，区分“标注错”和“执行错”。统计是否减少错素材、尺寸与字形返工，及是否增加不必要时间/token。收益不足的部分不设为强制步骤，不反复调整框线来让指标好看。

工具：scripts/annotate_ui_reference.py --input <input.json> --output <输出目录>。
输入包含 source(path/sha256)、canvas、elements，以及可选 inspect_prefabs。每项声明 id/label/category/rect/basis/annotation/uncertain；measure_face 和 match_asset 只在适用时填写。参数示例见本次 input.json，元素名、位置、颜色阈值和资源名均为案例数据，不是通用默认值。

工具只读输入和Prefab，输出 annotations.json、source_texts.json、reference.png、face_masks.png、overlay.svg 和 index.html。它不是OCR/语义检测器、字体字号求解器或完整Unity序列化解析器；不会解析Prefab变体继承与运行时行为。源码图像和对象范围由本轮AI选定；图上外观框仍带有估计误差。

## 标注后试组装（可选工具）

用户可以授权在未确认标注正确时先试拼；记录“授权试验”，不要改写为“标注已确认”。保留旧Prefab，用新副本比较结果。

配置先明确每个框的类型与素材策略。可见主体框需根据原Alpha留白换算；等比图标与显式拉伸底板分别处理，九宫格需单独核对边框，不能一律套等比公式。裁到的高度与被挡住的宽度不作为完整尺寸。保留项逐项注明原因。

文字配置同时包含默认字形目标、容器、自动字号上下限与状态排版。前缀/符号的显隐不靠普通文字关键词或无关的底板开关推断。有前缀、无前缀、长文案需保持同一组件可用，复用项目原入口或小幅扩展可选字段，不复制业务规则。

校准可以用单独的引擎字形截图测量一次高度/位置，统一调整字号和位移；不能非等比压扁字形以消除宽度残差。最终自动字号、容器和材质条件仍需一起复查，数值写入成功不等于最终字面达到目标。残差说明原因与影响，按收益停止，不形成追分循环。

相关入口：
- `compile_annotation_choices.py`：依据配置的rect_kind及既有布局资源信息，复用place_content换算主体框，保留已有stretch策略；不自动选图。
- `UIAnnotationVariant.Run -uiAnnotationJob <job.json>`：在独立副本应用配置，复用ConfigureTMP/CapturePrefab，保留原Prefab；输出组件、预览、单独文字样张。依赖已准备好的独立Unity工程，不是任意原项目一键改写。
- `calibrate_annotation_text.py`：限定浅色字面条件的一次等比字号/位置换算。越过预设比例范围就停止调查，不自动扩大搜索；不负责选择字体、材质或判断全部视觉质量。

低成本模型负责哪些选择、工具准备由谁完成、执行中给过什么反馈分别记录。工具错误不算模型能力失败；有主agent反馈的试验不能称完全独立制作。

## 完整组件取证的已知缺口

现有inspect_texts只提取TMP基础字段，不能证明完整文字样式已查清。使用原组件作依据时，继续检查同一节点挂载的其他视觉组件（例如TrueShadow）及嵌套实例覆盖；记录材质实际启用的关键字，不因保存了某组参数就认定对应效果已开启。未解析的覆盖应保持未知，不将基础Prefab的值作为最终运行值。

字面高度测量不覆盖描边/阴影外轮廓。边缘效果有疑问时，先在相同渲染条件下分别开关已有组件，区分贡献，再调整字号；避免把阴影误当加宽描边。组合素材应查完整子层和九宫格/旋转关系，不能只给简化替代图重新标位置。

本条是落实已有“完整组件/文字样式复用”要求，不增加新阶段或逐项审批。发现确切原资源仍未使用时，先处理该遗漏；边际收益停止原则不用于掩盖已知的低成本结构修复。

### 原组件最小对照的执行

复用组合控件时保留子层、切片、填充关系及同版本实例覆盖，数据值继续作为输入。先固定文字的字体、材质、字号和位置，仅开关被怀疑遗漏的效果组件，保存两张同条件截图；既检查参数来源，也确认真实画面发生预期变化。对照只能证明该组件的贡献，不能据此宣称其余文字参数已与效果图一致。

`UIAnnotationVariant` 在副本中支持 `replacements` 与 `effects`：前者填写原Prefab、目标/父节点、中心点、按源fileID定位的属性覆盖、保留的视觉组件命名空间及可选Slider预览值；后者填写目标节点、原Prefab和源组件fileID。`bindings.target_component_type` 可显式绑定原生控件。只复制当前任务所需视觉内容，不复制另一套游戏业务；声明白名单时仅清理新副本。源属性暂支持数字、布尔和字符串，其他类型明确报错。没有准备依赖的工程不能直接使用此入口。

工具按对象一次提交全部属性覆盖，避免旋转四元数等关联字段逐项写入时被引擎归一化。复制文字效果后自动输出 `effects_off.png`；它与默认图共用字体/布局，未包含在effects里的已有效果保持原样。保存重载、数据切换、旧输入回归仍走原入口，不为每个局部另写运行系统。

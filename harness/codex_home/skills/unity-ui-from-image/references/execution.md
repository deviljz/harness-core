# 换一张图：完整执行说明

新任务先区分美术设计交接与程序组装。美术阶段按[需求与状态设计](design_review.md)完成设计，不要求 Unity；进入程序组装后按[三个执行机制](mechanisms.md)做代表样、关系检查与独立复核。环境要求见[执行环境](environment.md)，不能用事后补记录代替执行顺序。

版本：2026-11-10，配合[通用规范v0.52](workflow.md)。设计检查与交接可独立执行，详见[需求与状态设计](design_review.md)；只授权状态检查时不自动制作素材。详细判断标准以通用规范为准。

输入若含元素合成描述、设计文件或部分标注，先按[通用规范的输入路径](workflow.md#按美术交接输入选择路径)复用可核实数据并补缺口；仅图才从识图建立描述。

## 这次要验证什么

验证“换图后仍能按同一规则完成：定义元素 → 分析遮挡 → 选方法 → 制作完整素材 → 验收 → Unity组装 → 检查与替换”。用户提供新效果图时，直接以该图开始，不先重画整张效果图来降低难度。

当前用户已授权新图自主跑完整流程。每步都留记录，满足完成条件就继续，不沿用上一轮逐小阶段等待用户确认的节奏。最后交付结果和失败/偏差说明。没有新图时不拿旧图或自选样本冒充这次试验。

当前会话沿用的要求：允许为拼装进行近似重绘，但大体效果、风格、主体大小和独立性不能有问题；文字、图标、状态独立；共享素材只做一次；按功能归组；竖屏9:16～9:21.7，含安全区；生成后尽量只留原生UI组件；少把大图送进上下文。它们是这次试验的要求，不是所有未来项目的强制参数。

不沿用上一张图的四种建筑、34素材、71节点、20文字、403×881画布、素材编号或坐标。取消阴影和格子花纹可忽略是旧图的局部特许，新图不能默认免检同类细节。

## 起步：先固定输入和独立输出

1. 保存新原图副本、文件哈希和原始尺寸。明确是一张页面还是多页拼图；给每页稳定编号。
2. 登记试验编号、使用的规则版本、目标尺寸/比例、字体策略、可用工具与实际授权。单一主页面先完整走通；用户给出多页且要求全部时，所有页面进入清单，不能只交一页后称整套完成。
3. 新建独立试验目录；Unity使用独立资源前缀、场景和Prefab路径。可复用现有测试工程，先核对当前打开的是哪个工程，不覆盖旧图已交付资源和用户修改。
4. 先检查现有组件、脚本的真实入口与参数，再选复用方法。不得直接运行当前案例的发布或测试入口，把旧图结果写进新试验。
5. 合理的布局/归属解释由AI决定并留依据；无法从图判断、且会改变玩法对象或主要交互的歧义再询问用户。
6. 按通用规范“还原依据”核对效果图、标注、现有组件、运行结果与配置各自负责什么；仅将不能从资料与已有授权解决的明显冲突集中交用户确认，不默默混用版本。可变区域在1.1记录模板、数据字段和现有入口。
7. 历史版本或独立工程验证，记录快照与适配的边界；在生成前先验证一个代表图片、文字和渲染画面，补齐运行时按路径加载的依赖、主字体/备用字体关系及关键包。不要等整页完成后才发现环境缺失；不能靠参考整图底板掩盖缺少组件。

## 素材处理的硬性区别

- 抠图只负责可见边界与背景，不能恢复遮挡后的内容。需要补全的对象必须补画或重绘，不能留下缺口然后在原位置拼回去掩盖。
- 文字与图标从底板分离时，也要恢复它们下面的底板。最终文字使用真实文字组件；预览字图不进入正式UI。
- 柔边、抗锯齿、区域半透、发光分别判断。透明PNG存在Alpha不等于透明正确；同时检查边缘颜色是否混进原底。
- 规则图形可以重建，但不能用简单铺色替代原本复杂结构；必须保留已约定的描边、厚度、高光、阴影和材质关系。
- 不强制Layer AI或固定“切两遍”。整图用于判断语义和布局；局部输入用于提取/补全具体对象。每次处理都要有明确输出用途，不能因为有局部裁图就再把同一素材重复做一份。
- 生成画布大小、主体可见范围、逻辑格位、UI显示框是不同数据。建筑/插画等比；九宫格只用于适合伸缩的底板。
- 模型输出可以偏离内容细节，不能悄悄改画风、大色块和主要比例。看实际尺寸和成组效果，不只看放大的单张图。

## Unity交付要求

按通用规范“配置内容、预览数据与正式界面”交付：重复条目和奖励由数据填充，效果图样例作为独立预览数据；复用已有配置、图标映射、价格／本地化和状态规则。标明本次是静态示意、可填充组件还是业务接入；仅有静态行和写死数组不能通过数据驱动验收。已授权实现时验证数据换组及刷新，无业务授权时不编造购买／领取逻辑；仅补规则或待确认时不改界面。

按钮拥有自己的底、图标、文字；卡片拥有自己的价格、图片、状态；功能区域决定锚点与伸缩。覆盖层为了绘制顺序需要单独放置时，明确它对应哪个对象。屏幕越长要扩展什么、越短要缩放/留白/滚动什么，先写规则再生成。

本次至少验证9:16、9:18、9:19.5、9:20、9:21、9:21.7，以及最短/最长两端的安全区；分辨率可以按性能选择等比例像素尺寸，不能把比例和某个固定像素值混淆。真实设备的安全区读Screen.safeArea，测试边距不能写成全机型常量。

正式场景只保留原生组件和有明确必要性的运行脚本。生成标记、测试计数、测试事件、临时控制器移除；稳定编号和映射放外部文件。安全区脚本是实际运行需要，不是生成脚本；“本例1个脚本”不是允许任何其他项目随意塞逻辑进去的指标。

点击检查分为：Button组件正确、Raycaster实际命中、事件执行、真实业务生效。没有业务规则时只检查前三项，不能编造保存、删除、扣费逻辑；测试监听不保存到正式按钮。

## 新输入与环境检查（先于Unity整页生成）

1. 按PROCESS的“每轮必须落实的检查”保留状态设计、完整代表组件、代表文字及最终组合状态证据。可放在现有视觉要求表/项目记录中，不另写重复文档。
2. 新布局设置 `require_image_policies: true`。每个Image/Button声明 `image_fit: contain|stretch|sliced` 和 `filter_mode: source|Point|Bilinear|Trilinear`。contain保持图像比例，stretch只用于允许伸缩的图，sliced需要四边border；可见主体范围仍需视觉核对，不自动撑满盒子。
3. 复用原素材优先使用 `filter_mode: source` 并填写独立工程内原纹理 `source_texture_asset: Assets/...png`；松散切图没有可读Importer时，查对应图集设置后显式填写并记来源。source目前继承采样方式，不宣称自动复制所有压缩/平台设置。新素材按用途选择，不能统一硬编码Point或Bilinear。
4. 先运行 `python scripts/preflight_ui_layout.py <layout.json> --workspace <图片相对路径根目录>`；它检查字段、类型、引用、哈希和共享策略，不能判断艺术质量。旧输入回归才使用 `--allow-legacy`。Viewport用Group，并由ScrollRect明确引用viewport_id/content_id。
5. 空工程先运行 `PreciseUI.UIEnvironmentBootstrap.Run`，与生成分开。命令行使用 `Unity.exe -batchmode -projectPath <独立工程> -executeMethod PreciseUI.UIEnvironmentBootstrap.Run -logFile <日志>`，**不加-quit**；导入完成或超时后自行退出。就绪检查同时要求 TMP Settings 与所需 Shader；看到 `UI_ENVIRONMENT_READY` 后仍需渲染代表字形，再运行正式生成。已有原TMP字体/备用字体/材质仍优先复用，此工具不替代原启动依赖调查。
6. `ConfiguredUITrial`逐个检查声明的图片显示方式，不再依赖手填等比名单。aspect_ids仍可补检必须保持比例的RectTransform容器。coverage.json声明自动检查覆盖与未覆盖范围；最后另做视觉/状态/动态检查，产物变化后重验受影响部分。初始导入报告不能代替后来动态组件的检查。
7. workspace是本工程私有目录，tool_workspace只读工具，两者分开。新任务用唯一runs子目录和显式配置调用ConfiguredUITrial.Run；active_trial.json仅供本工程手动预览，不作为并行任务入口。菜单 `Tools/Precise UI/Open Active Trial Scene` 在停止Play后刷新并打开指定场景，输出Prefab哈希。MCP每次操作指定完整实例ID并核对projectRoot，不能用重名工程名。已有未保存改动由Unity保存提示处理；仅截图并不表示可见窗口已经更新。

工具兼容性：旧布局缺策略仍按历史默认值导入，但新的覆盖报告标为未检查；严格新输入缺策略会在生成前报错。共享图片的导入采样必须一致；不同实例的显示盒子与fit可以不同。

## 什么时候返工，什么时候叫用户

视觉精修按通用规范的“由AI判断收益与停止边界”执行：达到阶段必要目标后，AI根据实际尺寸下的影响、下一次改善把握、成本、退步风险和复用价值自主决定是否继续。低收益细节留在现有问题记录，保留最佳版本并继续后续步骤；不把停止精修误作停止任务，不把未达标阻塞写成通过。无需每次请用户批准停止某个非必要细节的精修。

AI自行处理：可逆的目录/场景创建、合理的层级和锚点选择、已授权的制作、一般工具适配、错误修复、测试与文档同步。记录推断后继续；不因旧文档写“用户确认”就重复阻塞已授权的自主试验。

需要用户介入：缺少原图或必需设计信息；对象/玩法解释有实质分歧且无法从材料判断；必须用户登录/点击外部平台；需要新增付费授权或超出已约定尝试范围；原需求范围被迫改变。说明具体缺口、已完成什么、下一项最小操作。服务访问限制与工具失败如实区分，不能伪装成技术上不可能。

同类重试连续两次没有改善时，先回查输入范围、结构参考、方法与质量目标，不盲目重复同一句提示。它是本流程的复查触发点，不是用户总共只允许生成两次。费用/次数没有明确授权的部分不能自行扩张；已经授权的常规步骤无需逐次请示。

| 问题最早出现在哪里 | 应回退到哪里 |
|---|---|
| 对象定义错、共享关系错 | 1.1对应元素/类型 |
| 被挡部分漏记、底色污染误判 | 1.2对应完整性记录 |
| 方法不能满足已知必留项 | 1.3对应方法和条件 |
| 定义/方法正确但缺角、混底、风格或比例做错 | 1.4对应制作输入与结果 |
| 缺陷应在素材验收被发现但漏了 | 1.5漏项，同时保留上游根因 |
| 素材正确，层级/缩放/颜色/字体在Unity里错误 | 阶段2的配置或实现 |
| 替换、重开、重复导入丢绑定 | 阶段2实现和阶段3漏验 |

不因后面出错就全流程重做，只重做受影响的依赖；旧证据和失败阈值保留。新证据推翻旧结论，写明旧判断、新证据、新结论、日期和影响，更新当前摘要和生成模板。

## 最终交付与成功判断

- 原图及版本、元素/缺失/方法记录；独立素材与来源、共享和多视图关系；布局/层级/适配数据。
- 干净的Unity场景和Prefab、可编辑文字、测试配置、准确的打开方法和复现入口。
- 原效果图对照、当前素材离线参考、实际引擎截图、端点比例与安全区效果。只把必要的小图送进上下文，全尺寸文件留本地供用户打开。
- 修改文字、关闭/移动一个独立对象、切换声明的状态、至少一份共用底和一份插画替换、保存重开、重复导入/发布、原路径回归的结果。类别确实不存在时记录不适用，不能伪造测试素材。
- 每项检查的预期、观察条件、证据、通过/失败/未测试/不适用；仍需美术精修的部分和根因。
- 新图相比旧图复用了什么、改了什么、是否出现专用修补、试了多少次、哪些需要用户操作。单页成功仅说明这张图可复用，不等于任何图都稳定。

“完整跑一遍”指把承诺范围的各阶段真正执行并交付证据，不等于所有美术细节定稿，也不等于必须把未知玩法实现出来。流程执行完成、质量是否达标、待用户视觉确认三种状态分别写。

## 是否做成skill

已按用户要求先创建研发版 `unity-ui-from-image`，再用新图检验。文档承载规则与理由；skill负责让AI找到这些规则、读取本次输入、选择现有工具、按约定推进并交付证据。skill本身不会补齐代码能力，也不会提供模型账号或保证切图质量。[官方说明](https://developers.openai.com/plugins/concepts/skills)

封装时保留一个维护源：简短SKILL.md＋按需读取的规范/模板＋确实可复用的工具；旧项目的坐标、素材编号和一次性修订脚本只作案例。发布包应带齐必要文件或明确工作区依赖，不能靠本聊天或本机D盘路径才能工作。先在无历史聊天的新会话中验证输入、继续/停止条件、失败归因和输出，再逐步扩大适用范围。[官方编写建议](https://developers.openai.com/plugins/build/skills)

已有案例包括 `ui_trials/ink_home_20261106` 和 `ui_trials/racing_carnival_20261106`。赛车第二轮验证了外观版本区分、按职责设置的文字样式、可编辑分段强调与共用底板材质调整；参数和角色图案不是新页面默认值。最终结果以各案例 RESULT.md、iteration记录、evidence及Unity场景为准；尚未做无聊天历史的新会话或跨机器验证。

本轮新增礼包试验：设计检查与交接可按用户明确授权采用标注的试作假设继续；原图截断内容不补造奖励；原生滚动容器继续走既有导入入口。验收路径读取本次配置，缺少引擎参考图应报缺证据，不能静默跳过像素与变更检查。自动点击须在布局和首次绘制完成后执行。案例参数不进入通用默认值。

特效存在时：设计检查与交接使用effects_inventory模板标明证据与假设，1.1登记归属，1.2确认干净底图，1.3选择表现工具；阶段2～3检查开关、时序、裁切、状态生命周期与实际播放。若未覆盖，只能宣称静态/状态部分完成，不能用大量静态断言替代特效验收。当前共用UIEffectAuthoring与UI/ProceduralEffect仅覆盖参数化放射光和星光，不是通用粒子系统。

## 需要量化视觉差异时

按[指标辅助验收](visual_metrics.md)先冻结参考、局部范围、遮罩和状态。运行scripts/ui_visual_metrics.py --profile <配置>生成分项数据及小图；不要给全页打唯一总分。先用已知偏移/偏色/模糊对照校准，区分“测量能运行”和“能判断当前画面”。最终引擎截图须绑定实际构建，若修改前后完全相同先核查是否生效，不继续刷素材。当前工具依赖Pillow/numpy/OpenCV/scikit-image；只接受同尺寸不透明合成图，不自动对齐或优化。

2026-11-07补充：开工前标出目标界面和宿主背景／共用层的归属；只制作、统计和比较获准范围。按时间从Git选样须记录分支覆盖范围，不能把当前分支未找到当成整个项目没有。

原 TMP 字体材质可由元素 `font_material_path` 显式指定 Unity 资产路径，配套 `font_asset_path`；生成入口验证该材质与字体使用同一图集。原材质作为整体样式复用，不叠加临时描边样式参数；按实际文字检查效果。


### 旋转节点的几何回查

`pixel_rect`仍是旋转前的设计矩形；独立旋转节点用声明角度和轴心换算成轴对齐包围框，再与引擎导出的屏幕包围框比较。当前修正验证了无旋转父级下的单节点旋转，未展开旋转祖先对子孙的复合变换；后一类仍需独立核对，不以此宣称任意旋转层级已支持。


归属检查入口：`python scripts/check_ui_scope.py --plan <归属声明> --observed <正式Prefab观察值> --output <检查结果>`。声明提供四类归属、依据、禁用预览依赖/节点、正式子树及无渲染挂点；观察值来自正式导出重载。工具核对声明覆盖、预览数据/依赖、子树、引用及挂点，不自动判断语义归属；未知必须先查证。不要把某案例节点名或尺寸写成通用默认。

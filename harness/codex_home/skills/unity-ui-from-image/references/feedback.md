# 导出本周使用反馈

美术和程序每周把使用本skill的记录交给流程维护者分析。用户说“导出本周使用反馈”或在使用对话中说“导出反馈”，就执行本约定，不让用户重新列附件清单。由用户触发，不创建定时任务、不自动上传或给别人发送。

## 范围和内容

“本周”按用户本机时区的当周截至导出时计算，记录实际日期范围；用户指定范围时按指定执行。当前对话默认纳入；能访问其他对话时，只查本周使用此skill的相关任务，匹配不明确的集中确认，不导出无关聊天。拿不到其他对话时先导出可访问部分，说明覆盖范围并请用户提供相应记录，不称已导出全部。

每个任务应包含以下实际存在的资料，不仅是聊天文字：

- **对话与过程**：用户指令、AI答复、澄清与确认、关键工具调用/报错及处理结果，按时间顺序保留。相关子agent工作纳入或明确未取得。原始记录能取得就附带；摘要用于导航，不能代替对话。不要导出隐藏推理，记录中未提供的原因不自行编造。
- **输入与依据**：原效果图、用户附件、相关局部参考/状态图，以及本次实际采用的规范、字体样张、组件样张和版本。对话中的图片必须有对应文件，不能只有临时路径、图片占位符或失效链接。
- **输出与变化**：生成/拆分资源、交付清单、布局描述/标注、对比图、Unity实际截图、错误截图。保留与问题有关的失败版本和修前/修后图，并标明各自属于哪次尝试；不只留下最好的一版。涉及动画或点击时附已有录屏/动态证据，没有则注明。
- **可复查资料**：涉及问题的Prefab/场景、生成配置、相关修改/补丁和必要日志。只收本次所需部分，不复制整个工程、Library或全部素材库；大文件/授权限制导致未附带的，列出文件名、来源、版本/提交和缺失影响，不把引用当成已附带文件。
- **环境与问题摘要**：skill版本、实际入口（美术/程序）、任务目标、软件/插件版本、模型及思考档位（有记录才填）、卡点、人工修正、最终是否接受和剩余问题。用量/缓存数据能取得才附，未知就注明，不估算成事实。

## 收集与打包

1. 用当前环境实际可用的对话读取/导出方式取记录；支持分页时查到所需日期，检查工具是否截断。不能把当前上下文摘要、最近几条消息或截断的工具结果当成完整记录。不要假设某个聊天导出功能一定包含图片。缺少历史或附件时在缺失清单中写明，并集中请求必要资料。
2. 复制相关图片和文件到导出目录，保留原分辨率与透明通道；缩略图只用于浏览，不代替原图。重复文件可按哈希去重，但保留每次引用关系。记录对话/任务标识、时间、消息或轮次定位、文件相对路径、用途及SHA256，避免同名图片覆盖或原图和结果混淆。
3. 生成一个ZIP，内部保留“先看这里”索引、按任务分的对话和附件、文件清单与缺失清单。索引明确标注“美术效果图”“本轮生成结果/Prefab截图”“修前/修后”，并连接到包内文件；不要求使用者安装Unity才能看对比。可用Markdown或HTML，选择本次最简单的形式。
4. 打包前移除凭据、访问密码、账号令牌及无关个人信息；保留脱敏位置和诊断所需上下文，不为脱敏删掉关键图像证据。原文件不改。仅生成本地包，由使用者按团队渠道发送。
5. 解压到另一临时目录核对：对话覆盖时间、附件数/哈希、索引链接、图片可打开，尤其检查用户指出问题所对应的图片。检查完成清理临时目录。缺项不能静默略过：最终说明“完整”或“部分”，缺什么、影响什么判断，并给出ZIP路径。未做的验证如实注明。

## 平时少做一点保留

任务过程中保留输入引用、关键修前/修后结果、来源与确认记录，放任务目录，不只放临时附件目录；沿用已有任务记录，不额外写长周报。不覆盖用于判断失败原因的关键版本；其他重复临时产物及时清理。周末由AI整理索引，不让美术/程序手工收集所有截图。

这是反馈导出规范，不是已实现的跨应用一键导出器。当前环境拿不到的历史、图片或插件内部数据必须列为缺失；用户确认后再补，不虚构恢复结果。

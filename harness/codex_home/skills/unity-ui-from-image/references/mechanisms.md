# 代表样、视觉关系与独立复核

适用于新制作/组装与模型小任务测试。只做用户授权阶段；小任务不用生成整页。详细标准按需查PROCESS、NEW_IMAGE_RUN，不默认读取全部历史案例。

## 程序批量拼装：固定两个子 agent，逐界面放行

一次任务涉及多个界面时，主 agent 先列界面清单，把同一界面的不同状态归到一起。整批必须创建并持续复用同一对独立子 agent：一个制作、一个复核。主 agent 负责派工和放行。每次只派一个界面，返工仍交给原来的两位；当前页放行后才派下一页。两位各自保持角色，不互换或再分派给其他 agent。

- **制作**：直接读取本 skill、本页资料和已通过的共用组件。按适用步骤核对依据、复用资源、组装和引擎自检。新组件或新组合先把代表样交给复核者，通过后再展开；复用已通过的组件时记录原样和本页新增关系。
- **复核**：在代表样和整页两个节点独立查看本版本证据。先对照效果图和 Unity 实际画面，判断明显错图、缺项、布局和状态差异；再从任务记录、产物版本和检查结果核对适用步骤及先后顺序，尤其是代表样是否在展开之前通过、修复后是否重验本版本。记录合理跳过某步的依据。只有制作方口头声明、缺证或事后补写流程，不能据此判流程通过。复核者返回结论和问题，由制作方改。
- **放行**：把“画面核对”和“流程核对”分别写入现有阶段复核记录；使用 review_gate 时把二者列入 criteria，逐项写观察与证据位置。两项都通过才展开或转页。有一项未通过或无法判断，就把具体问题退给制作方补改或补证，然后由同一复核者重查受影响项。用户已确认的小差异照原约定处理。

主 agent 沿用现有任务清单记录两位子 agent 的身份、当前页、对应版本和两项结论。工具若无法提供独立子 agent，就明确说明该批量流程的限制。

## 先做什么

1. 冻结本轮输入、允许变化、必须保留的关系。选一个完整代表组件；如果涉及跨条目覆盖，代表样包含相邻条目。放进格子的组件要连同外部底框核对，内部样式检查与容器定位检查分开；居中设计默认零偏移，不沿用无依据的旧偏移。文字按职责选代表样。画布缩略图不替代实际尺寸的必要局部。
   遇到跨页共用元素，在做代表样前按[组件选型约定](design_library.md)查一个现成用法。复核时看实际沿用的组件或资源，以及本页按设计应保留的变体；上层界面已有的公共栏一并核对归属。
2. 新布局使用 `workflow_version:2`、`execution_phase:"sample"`、`require_image_policies:true`，按既有导入格式生成小样。每个图片声明image_usage（illustration/icon/panel/background等）；插画/图标使用stretch必须附stretch_reason及设计依据。保持比例不代表裁切/主体大小已正确。
3. 执行能自动检查的关系和数据变化，生成实际截图。填写review_gate.json（模板见templates/review_gate.json）：只追踪当前代表组件所依赖的素材/定义/样式及检查结果，不把无关全页文件纳入以免不必要重验。
4. `python scripts/ui_review_gate.py prepare --config <gate.json> --stage sample` 生成最小复核包。交给未参与制作的另一会话/agent，视觉核对提供效果图、结果图和验收要求，批量任务另提供流程核对所需的原始记录和版本证据；不提供制作者的预期结论。完整流程已授权时可使用一个独立复核agent；用户指定单agent/不委派时服从用户，明确独立复核尚未完成。模型有疑问时返回uncertain，不勉强通过。
5. 独立复核写JSON后运行同一工具 `check --stage sample`。通过才允许 `execution_phase:"assembly"`，并填绝对路径review_gate；原Build入口会检查当前代表样证据。新输入先跑preflight_ui_layout.py。工具不阻止探索草稿，但未检查的整页草稿不能冒称已按代表样流程完成。
6. 最终运行结果使用同样的独立复核，`prepare/check --stage final`。准备final包也要求sample有效；影响已验收项的输入变更会使旧包失效。低收益小偏差可列polish；缺元素、错误状态、关键遮挡、明显比例错误不得用polish标签绕过。

### 代表样里玩家必须读到的文字

制作时按当前状态挑关键字段，例如购买数量、价格或确认操作。用绑定数据给出预期值；声明和数据文件列入该阶段的 `inputs`。拿两行重复条目做代表样时，每行有自己的标识和预期值。无需登记每个装饰字。

- 通用 Unity 试做配置填 `"required_text":[{"id":"quantity","expected":"500 金币","case_id":"reference"}]`，id 对应节点清单。按设计隐藏时填 `{"id":"quantity","hidden":true,"case_id":"empty"}`；节点应存在。同一对象换状态的项目自检在实际绑定数据、更新 Canvas 后调用 `PreciseUI.UIRequiredText.Inspect(label, expected, hidden)`，将返回的空串记为通过，非空诊断记为失败。
- 在该阶段已有的复核配置中填 `"required_text_checks":{"sample_checks.json":["reference:required_text:quantity"]}`，文件名与 `checks` 相同。每个名称对应一条引擎检查结果；可使用 Unity 原始报告的 `tests` 或项目自检报告的 `checks`。通用离线验收会核对原始 Unity 报告，将配置所要求的逐项结果带入汇总报告，两种报告均可用于复核。旧报告只有总通过、文字框位置或字段值时，需要补采证据。新模板的 null 表示尚未填写；该阶段确无关键文字时填空对象 {} 即可。
- 独立复核仍看同一状态的截图，确认数量和价格可辨、没有被上层遮住。整页再查代表样未覆盖的差异，例如不同档位的图标轮廓、列表占幅和页头。

### 换配置或素材后，哪张截图还能用

采图时沿本页实际绑定查一次：哪个配置决定当前状态和图标，加载了哪份外部素材。按本次实际使用的文件填写 Unity 试做配置的 `render_inputs`，路径相对工程根目录或使用绝对路径。复核配置的同名字段列本阶段依赖，路径相对复核配置或使用绝对路径。没有这类外部输入填 `[]`。复核者可直接沿现有绑定或配置核对这几个文件；资源来自服务器或只能取得历史截图时，交付说明注明实际验证的数据范围。

Unity 试做随本次截图把输入及输出的 SHA256 写入原始检查报告 `capture_files`；离线汇总保留这份记录。项目自有采图入口沿用同一格式，在状态绑定前记录实际来源，在这次出图时记录新截图，确认采图期间输入未变。复核配置的 `candidate` 使用这次采集的截图；需要看局部可从该图裁出对照。复核工具检查配置、素材和对应截图是否在同一份采图记录里。发生变化时重新采受影响的状态；只重新打复核包或拿旧截图补记今天的文件值都不能证明新版已看过。

### 相似状态怎么核对

确认弹窗、领取前后等状态容易看串。复核时一次只把本状态的原稿和实际画面摆在一起，在已有复核记录中写一个能区分两种操作的细节。例如两种弹窗都有“继续编辑”，要看主按钮确认的是清空还是放弃修改。图标、选中对象或按钮归属也可作为区分依据。与设计冲突时先重开这一对原图再退回制作；截图只能确认画面，对点击后的结果按实际试玩记录判断。

## 三种关系先够用

layout.visual_relations按需声明，每条有id：
- `draw_above`：node必须画在other上面。用于覆盖层、按钮、相邻条目等；需实际同时激活。工具检查实际Canvas绘制深度，不只看声明draw_order。跨Canvas排序暂未自动支持，返回未通过，不猜顺序。
- `contained_by`：node的屏幕边界在other内，tolerance_px由本次设计决定。它不能代替滚动裁切/输入验证。
- `visible_if`：node显隐与state_field布尔输入一致。运行检查由本次调用方提供状态；测试保持同一文案切字段，再保持字段换文案/语言。不能用特定文案关键词猜业务状态。
没有适用关系时填写relations_not_applicable_reason。UIWorkflowChecks.ObserveAndCheck从实际引擎对象导出位置、绘制深度和显隐；ui_visual_relations.py统一检查。ConfiguredUITrial自动接入默认画面，可通过reference_state传本次状态；其他动态状态必须在自己的数据入口执行后复用检查函数。

自动检查无法判断选错素材、插画裁切是否贴合、字形是否合适。独立复核必须看图，指出具体区域/差异，不以通过项数量或脚本退出码代替。rect检查坐标来自实际屏幕；关系只检查已声明范围，不能宣称覆盖未声明设计。

用户反馈具体偏差时，先锁定其正在看的产物、版本、显示模式和指出的对象，再复现该偏差。位置问题先查实际画布及相邻定位关系，不用素材轮廓、颜色或动态特效的差异替换问题；仅测单个对象绝对坐标不足以否定用户观察。尚未复现时列出已知条件与未验证项，不提前宣布“不是位置问题”。

状态检查的预期先从设计图/已确认需求和原入口独立列出，再与新实现逐项对照；不能只遍历新代码已有的字段来宣布状态完整。父级状态可能同时改变行底板、子格底图、特殊边框、图标或文字，须核对每个受影响对象及普通/特殊组合、切换和恢复。发现遗漏资源切换或有明确来源的错图时，不以“小色差”延期；只有实际实现并检查的范围才能标为通过。

涉及尺寸选择或换档时，复核包按[尺寸判断](design_library.md#尺寸判断先核对尺度再分项比较)包含同倍率局部并排图、实际图标尺寸和尺度依据；复核分别评价图标、数字、底框、位置，不接收只有“更疏松/整体更合适”的通过理由。资料不足返回uncertain，由主agent补查关键证据；两个模型一致也不免除这些检查。

## 从局部推进整页

代表组件通过当前阶段目标后，冻结其版本与已接受残差，整页复用真实Prefab和更新入口；不要为了整页再次从图片或旧近似脚本重建同一个组件。复用已有页壳属于接入验证，记录来源，不冒称从零独立完成新图流程。局部许可不扩大为整页已验收。

先列整页新增的组合要求：相邻实例覆盖与间距、滚动裁切、固定区/伸缩区、安全区，以及局部未出现的状态/内容。只为这些差异补查原组件或最小样本，不重复分析不变素材。业务状态来自显式数据；当前行、已达等级、奖励锁定、领取、内容缺省不能互相猜测或从文案推导。页面只组织已有显示入口，不能绕过组件另写一套奖励判断。

整页缩略审查还要核对局部样本未覆盖的独特元素，例如页头、主要插画、大奖和独立特效。缩略图看不清的关键处补一张同倍率局部，不把“重复格子通过”当作这些元素通过；只补必要区域，避免整页反复进上下文。未找到可复用实现的差异与低影响精修分别登记，不能把未修写成已还原。没有值得本轮修改的问题时交付验收结论即可，不为凑版本复制同内容Prefab或进行无依据修改。

验收先排新组合错误，再列继承的精修项。旧组件可用仍需整页同数据/同状态对照，以及同实例连续换组、空组/恢复、真实滚动/点击和比例端点；仅验证归一化滚动数值或触发回调，不等于输入命中与裁切正确。局部未验证的动画、业务、真机范围继续保留为未验证。模型能填局部配置，不自动升级为能做整页接入或独立审图；按职责分别记录能力与主agent介入。

同时核对交付场景的直接启动入口：运行时事件订阅不能靠已保存的编辑器实例保留，测试主动调用刷新也不能替代用户直接按Play。场景预览数据驱动与正式Prefab分离；测试先检查实际启动后的显示和事件，再主动换数据。指针检查取最前面的实际命中对象及其父级处理器，不跳过遮挡对象寻找后面的可用按钮/滚动区。

用户查看编辑态或Prefab预览时，还须核对该实际入口与报告截图的版本、Canvas尺寸、安全区及布局刷新是否一致。截图工具主动调用布局不代表编辑态会自动更新；离屏相机或独立Canvas也不能直接套当前Game窗口的Screen尺寸。沿同一个布局入口修正刷新，分开验证编辑预览与截图，禁止用子元素偏移补偿整组适配错误。

共享编辑器中只保存本轮明确修改的资产，优先使用目标资产的SaveAssetIfDirty与Prefab保存入口。AssetDatabase.SaveAssets会同时保存其他已dirty资产，未经范围核对不得用作生成脚本的统一收尾。保护检查发现来源不明变化时保留证据，不自动回滚用户可能的改动。

## 复核包与职责

门槛配置一次列好sample/final路径。inputs只填该阶段可追踪的设计/素材/布局/代码文件；checks填包含passed:true的机器报告；criteria只填适用视觉要求。schema2包按本阶段配置和共享设置绑定，其他阶段的路径/配置变化不使它失效；本阶段要求、依赖或共享设置变化仍需重建包并重验。旧schema1包仍按整配置哈希保守核查，不静默降低旧包要求；迁移只有元数据变化时由原独立复核者核对图片/标准/依赖一致后继承。最终inputs包括实际Prefab、必要运行脚本和状态数据，candidate是该版本的真实截图。报告必须绑定packet_sha256并逐项记录观察。

工具验证文件、版本、检查结果和复核记录，不会自动鉴定美术质量。不同reviewer_id也不是身份安全机制：由调用方记录真实独立agent/会话，不能让制作agent换一个名字自评。复核包排除制作者结论；保留旧失败和旧包，不靠覆盖文件抹去历史。

复核默认一个候选版本一个包；同版本的必要状态/局部可同包。多个候选比选时明确图与结论的对应，不因节省调用而混淆版本。复核者通常只需1张整体验收图及必要局部；返回重要差异、严重程度和位置。不组织多agent争论，不自动无限返工。能确定的修复采用后只重验受影响范围；证据不足则明确未知，按用户授权处理。

## 低成本模型测试

### 限制执行范围，而不是把案例答案写成通用规则

采用三层分工：通用校验工具检查声明是否合法；项目配置提供已确认的素材、组件、字体/材质、尺寸策略和版本；组件适配器调用该项目已验的生成/更新入口。页面模型负责选择和填写允许参数。项目没有现成组件时，先报告缺口并在本轮授权范围内制作、验证适配器，不能套用其他项目的组件或把近似色块冒充原组件。

项目配置由规则维护者准备并冻结，制作者不能改配置、阈值、组件内部实现或独立审图结果。它允许的是本次职责所需字段，而非永久禁止设计变更；新增规范、人工改资源或组件版本变化时，核对变更后发布新配置，只重验受影响部分。不把某次页面的84档、中心偏移、字宽或数量格式变成跨页面/跨项目默认值。没有离散档位的项目可以声明连续范围；空配置不是任意参数都合法。

工作区 `scripts/compile_component_declarations.py` 是这一方式的首个小适配：读取外部固定哈希的项目配置，核对项目ID、依赖文件、素材候选、字段类型/范围/可选档位，拒绝未知字段、重复键、非有限数字和未支持适配器；成功后仅输出数据。`UIRestrictedComponentSample` 消费调用方固定哈希的编译结果，复用 `UIDesignComponentRecipe` 的实例填充、缩放、居中和审计，生成独立局部Prefab；不生成完整页面。现有适配器仅支持已核对的方形图标＋数量，其他组件须实现自己的适配，不能宣称任意UI已支持。字段合法不能证明选图正确、视觉位置正确或文字放得下，仍须引擎审计和必要视觉检查。样本画布显式声明参考尺寸，保存重载后核对实际屏幕框尺寸与位置；局部字段正确不能抵消Canvas或祖先缩放错误。

哈希由调用方固定，不能让制作者同时提交替换后的配置和“期望哈希”。执行前再核对编译结果与依赖，输出到调用方指定的新路径，不覆盖已有交付。此机制控制通过该工具的输入，不是操作系统权限沙箱；若agent仍可任意改文件/运行代码，必须检查实际改动和调用记录，不能声称技术上已阻止一切越权。原稿/标注/旧整页的读取范围继续按本次任务约定，不因工具校验自动获得独立性证明。

低成本试验先固定任务、输入和工具，明确记录谁准备候选/组件、谁做视觉判断、谁只填参数。分别验证正常输入和拒绝输入；跨项目合成配置仅证明校验机制未写死案例参数，不代替第二真实项目验证。独立制作模型与复核模型分别降档，不把配置执行成功当成素材匹配、整页制作或审图能力通过。

重试按新证据和影响范围决定：同一问题完成一轮修复仍无新证据时停止盲调，只升级该局部；工具/输入错误先修输入或工具。实际总成本包含准备、执行、复核和返工，能取得时将主agent协调用量单列；只拿到子agent记录就明确不含协调成本，不能将它冒充整轮成本。推理已计入输出时不重复相加，缓存输入是输入的子集。相关任务优先复用已有上下文，固定规则前缀，避免为委派拆出大量小任务；能直接由程序完成的步骤不再开agent。具体模型与思考档位留在试验记录，不写成所有项目永久要求。对照试验区分任务范围与工具版本变化，不把混合角色工作总价解释为纯模型性能差异。

### 先把素材选择与尺寸换算分开

查原组件只为资源或样式时，使用固定字段输出入口，不能打印整对象后靠模型自行忽略页面坐标。`scripts/inspect_ui_image_styles.py` 复用现有Unity序列化读取方法，接受授权源文件哈希与明确节点名，只返回直接序列化的Image资源/type/ppu/颜色/材质等白名单，不返回RectTransform、祖先/兄弟节点或页面布局。节点重名、缺直接组件、变体/继承未解析时明确失败，不回退整页dump。它是程序阶段的读取工具，仍须限定允许源文件；不是OS权限隔离，不能证明可使用任意原页面资料。需要布局字段时另声明具体范围与依据。

已有资源时，先记录所选切片/外观版本、候选排除理由和来源依据。遇到半张纹理、镜像、前后层底板，查原组件的组合关系；不能因为只找到一张切片就用简单形状代替完整组件。具体资源名与坐标留在项目输入，不进入通用工具。

记录目标**可见主体范围**及其依据，再换算Unity图片框。透明留白不等于主体；被遮挡图案要结合原素材比例推断完整范围，并注明不确定部分，不能把露出的部分当成完整图案压缩。软光、投影、散点不能仅凭固定Alpha阈值判定主体，必要时使用有依据的手动content_rect。

工具工作区 `scripts/compile_ui_asset_choices.py` 从choices JSON生成新版sample布局：复用已有content_rect定义/主体测量，调用 `ui_package_contract.place_content` 等比计算图片框，保留完整原像素和Alpha；输出尺寸推导记录，拒绝缺来源/匹配理由/目标依据和哈希变化的输入。它不自动找图、认证选择理由或恢复遮挡。原有裁切导出路径仍保留，不把两个适配路径串联造成二次裁切。

静态Image/Group局部用 `PreciseUI.UISampleBatch.Run -uiSampleJob <job.json>`，job含layout/output/folder，复用原Build/CapturePrefab，生成真实尺寸检查与去生成标记的Prefab。模型交配置即可，不为每次局部试验写一套Unity生成/截图脚本。这个入口尚不承担文字、状态、交互或动画验证。选择是否正确、主体是否接近和组合是否完整仍交独立审图；几何检查不能代替这些判断。

完整试例和输入格式可查工具工作区ui_trials/asset_fit_20261109，但不复制它的具体资源/目标范围到其他图。只把任务交给低成本模型填写配置时，单独记录是谁准备了候选、谁判断了主体范围；工具准备成功不等于该模型已能独立制作。

先固定工具与任务，再比较模型；测试输入、验收标准和推理档位记录清楚。优先小范围的素材匹配、相邻元素/状态、插画或文字对齐，不能用会看错题答案的“测试”证明可独立制作。Luna从明确小任务起步，出现真实能力不足再对相同失败任务试Terra、Sol；工具缺陷先归工具，不算模型答错。通过只说明这些任务够用，不扩展成任意UI或全流程已证明。

记录制作、复核、修复的总用量；拿不到真实token/计费数据时明确未采集，不用输出字数冒充。避免同一失败无新增证据反复试；模型只读取变化文件/错误摘要，图片优先局部。机制测试、模型测试和实图生产分别报告。

模型选择按职责分别验证：能填对配置，不等于能可靠审图。复核测试同时包含正确与错误候选，检查误报和漏报；模型说出不存在的差异时不能据此改图，应回查原始证据并考虑升级复核模型。单轮校准结果放案例记录，不写成所有项目永久指定某型号。

对可填数据组件，机器证据补充实际运行中的连续换组、状态恢复和指针事件。测试驱动给 UI 更新留实际帧；若同帧测试失败，记录差异并检查测试时序，不直接归为制作模型能力不足。视觉内容与标准均未变、仅交付引用结构或检查代码改变时，可由原独立复核者核对图片哈希与要求一致后继承视觉结论，绑定新包；不得由制作者代签或默默沿用失效报告。


### 界面归属与正式交付检查

设计前按“本界面自有／共享复用／仅宿主预览／未知”声明可见对象和依据；未知先查资料。压暗不能单独决定归属，自己的遮罩和disabled状态仍可能自有。只验自有范围及本页采用的共享组件，不重做宿主画面。正式导出再执行一次归属检查：不含宿主图、重复宿主UI或有渲染的占位；挂接点应无渲染和输入。仅将previewData设null不够，还要用空数据清除已保存动态值并验证恢复。示例数据与宿主组合放Preview层，保留自身遮罩/输入拦截，开关与页面一起生效。

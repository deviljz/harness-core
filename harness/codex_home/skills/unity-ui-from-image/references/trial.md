# 试用版入口

先分美术/程序任务，按需读取规则，不要求美术运行 Unity。试用包的 START_HERE.md 是给人的短说明，INSTALL.md 是环境准备说明。

- 美术核心入口是“准备交付”：图稿认可后，自动检查状态、复用/导出或补齐必要元素、整理交付资料供美术查看，不进入Unity。具体按[准备交付](design_review.md#准备交付美术的核心入口)执行。创作方式不限制；只要求检查时不扩大范围。
- 程序：检查交接与工程 → 复用资源和完整组件 → 代表样 → 拼一张 → 实际引擎验收。批量任务按[固定两位子 agent 逐页制作与复核](mechanisms.md)执行。只恢复本界面所属内容，预览背景与真实业务分开。
- 程序的代表样声明各状态下应显示或隐藏的关键文字，按[关键文字复核规则](mechanisms.md#代表样里玩家必须读到的文字)从 Unity 取得逐项字形记录。复核时在实际引擎截图中确认最终可读性与遮挡。
- 输入可为图片、部分标注、可验证的描述文件或混合；只补缺项，不强制重新识别已可靠的数据。
- 新试用任务不增加功能或追求像素一致；优先解决阻塞、错图、错布局、明显文字错误。剩余低收益偏差注明后交付。
- 交付清单必需，完整精确标注不强制。保留已有可靠描述及其来源，测量/推断字段标为估计，未知就注明；程序只补未完成项，不重复拆图。本次不扩展自动维护素材库。

## 初始化信息收集

每个新任务由 AI 主动完成，不依赖用户填写模板或记得提供资料：

1. 根据本次要求选择美术或程序入口；只有任务范围不清楚才问。先查对话、附件、已知项目记录和用户指定目录，找到已有资料就复用；不为初始化扫描整台电脑或分析全项目。
2. 按对应入口核对下列信息。尚无路径、缺资料或版本冲突且影响本次任务的，整理成一组短问题集中询问；问位置或选择，不要求用户手工列全库。已明确没有的记为缺项，不反复索要。
3. 在当前任务记录中简记资料位置、采用版本、输出范围与未确定项，继续不受影响的工作。新项目只整理本次需要的内容，不以完整建库为开工条件；关键缺项未解决时不擅自猜定。

- **美术入口**：核对本次需求/效果图/原型、图片素材目录、字体和材质效果样张、通用设计规范与组合组件图文示例，以及复用/新增范围和交接位置。美术只需可查看的资料，不要求提供 Prefab、TMP 材质文件或安装 Unity。没有样张/组件目录时说明需程序提供导出资料，先开展可做的设计检查，不擅自让美术反查工程。
- **程序入口**：核对 Unity 工程和版本、美术交接目录（效果图、状态图，有则附标注/描述）、图片资源、TMP 字体/材质、通用 Prefab/组件、阴影等实际依赖，以及输出位置和允许修改范围。先从工程及现有目录查真实引用和版本，不让用户逐项报资源名；找不到或存在实质冲突才集中问。优先沿用美术侧的资源/规范编号并核对工程映射，不另建一套相互脱节的库。

## 项目与任务隔离

- `tool_workspace` 是解压包的 runtime，只读脚本与工具；skill安装目录也不存任务文件。`workspace` 是当前项目的私有工作目录，Unity默认 `<工程>/.ui_pipeline`，配置 `project_root` 必须与实际工程绝对路径一致。美术无Unity时使用当前设计项目自己的交付目录。初始化由AI确认路径，不让用户管理临时文件名。
- 每次新任务用 `runs/<任务名>_<时间或唯一编号>/`，独占布局、描述、报告、截图和反馈，不只靠任务名区分。重试沿用同一任务并留版本；另一对话的任务新建目录。生成Assets也用对应独立子目录，不能共用Prefab输出。
- 优先显式调用 `ConfiguredUITrial.Run(<本任务配置绝对路径>)`，任务配置指定自己的pipeline_config、layout、hierarchy、evidence。pipeline_config的workspace可指项目私有根或任务子目录；工具代码始终从tool_workspace读。`active_trial.json` 和默认布局仅是工程内的手动快捷入口，不作并行任务协调器；新任务用显式路径，不在runtime写全局指针。同一Unity Editor的写操作仍串行，不宣称同工程多任务可同时改场景。
- MCP枚举实例后，每次访问工程须传 `--instance <完整name@hash>` 和 `--expect-project <工程绝对路径>`，同一次会话选实例、读project/info核对、再执行；失败停止，不回退默认active实例。只有实例枚举可不绑定。编辑器重连后重新枚举，不能仅用client这类重名项目名。调用其他MCP接口也执行同样核对。
- 原安装器把workspace/tool_workspace都设runtime，是旧版缺陷。旧任务按来源拆开复制到各工程自己的任务目录，更新配置中所有绝对路径与图片根，再核对引用；不直接搬空共享目录，不批量替换所有路径，不改已验收Prefab。旧工程脚本升级按INSTALL.md，配置不兼容时工具会先拒绝，不自动猜归属或覆盖。

## 发布与失败处理

- 导入前检查任务的资产目录、文件名冲突和人工改动。已有生成目录缺归属记录、或旧发布记录缺场景哈希时，用新的输出路径保留现有成果。新目录承载同一任务的后续重导。Prefab 与场景保存并核对后才更新发布记录。
- `ConfiguredUITrial.Run` 负责生成本轮证据并还原编辑器的临时配置。可捕获的生成、截图或报告写入失败会触发本轮产物回退并把失败返回给调用者。验收过程只操作本次生成的资产和预览副本。编辑器进程强退后的恢复需检查磁盘及版本控制状态。
- 样本和标注变体的批处理入口使用本任务的新输出目录，按实际生成目录取 Prefab，只保存本次资产。交付检查和生成依然可在已连接的现有编辑器中运行。
- 离线验收要求非空且通过的本轮 Unity 检查。布局、配置、Prefab、场景、参考截图以及发布记录要对应，缺项、旧证据和校验失败均返回非零退出码。已有旧报告需要重新验收。退出码与报告都通过后，再做独立视觉确认。

## 描述交接与数据更新

随包提供 `scripts/convert_handoff_layout.py`，接受 `--layout --manifest --semantics --data --workspace --output --phase sample|assembly`，assembly 还须提供有效复核 gate。其输入契约见源码和 `scripts/tests/test_convert_handoff_layout.py` 的最小合成示例；不是任意设计文件导入器。先保留原布局/顺序/编号，再由显式语义表指定控件类型、父级、文字和归属。转换器不会自动连线业务组件。

通用脚本 `UiDataBinding.UIBoundFields.ApplyJson` 只更新已显式连线的字段。`UIDataPreview` 仅用于预览；`UIFitReferenceContent` 按指定参考尺寸适配。需要 TMP、uGUI、Newtonsoft.Json。已有项目优先适配原数据入口，不能创建另一套奖励/商品业务规则。

已验证一张奖励页在同一实例上修改数量时，两处关联文本更新，布局及其他区域保持。当前试用版的实测范围见随包 VERIFICATION.json，各任务的画面、状态和交互以本次任务的引擎报告为准。

## 安装和维护

收到新版完整包的安装/升级请求时，先读包根 AGENTS.md 和 INSTALL.md。已安装则用 `install_trial.py --upgrade` 检查旧版、备份并更新本次项目工具和配置；中断后先 `--recover`，再重试。只迁移已确认归属的资料，汇报备份位置及验证结果。正常制作任务继续使用项目当前版本。

每周由使用者说“导出本周使用反馈”，按[反馈导出](feedback.md)收集对话和图片等关联资料，生成本地包供团队分析。只有文字不算完整；缺记录、图片或版本必须列明，不要求用户重新记住需要导出什么。

整个试用包包含 skill 和 runtime，安装器保存本机工具路径；只发 skill 的旧 zip 无法替代完整包。不得带作者 local.config.json。工程安装遇到已有工具/重名脚本时先核对并复用，不盲目覆盖或复制第二份类型。

暂时保持一个 skill，两个入口，共用一套规则和工具。需要独立安装、独立维护且边界已稳定时再拆；当前不为未验证能力建立额外 skill。

# Camp 网页取样与 Prefab

- 仓库内 `02_Formal_UI` 是运行态 UI 依据。查交接与本轮对应提交；网页正式壳、网页玩法和历史包不能混用。Unity 正式源码在 `game/client`；测试构建按项目工作流用固定 Windows 路径。
- 现行 Camp 由 C# 组装单套 uGUI，文字直接使用 TextMeshPro。正式网页仍通过实际浏览器取样作为参照。下方整页 Prefab 与 Toolkit 流程适用于历史版本，当前主干应沿 `CampApp` 的实际页面入口核对。
- Camp 的视觉基准是 PC 桌面浏览器正常打开的正式网页。截取实际游戏内容框，对齐同一存档、操作和动作相位。Unity 手机版按这套效果还原，并在手机上验证长宽比、安全区、操作和性能。
- 已有 `game/Work_Local/CampWebSync/reports/ui-fidelity-review` 收录同存档 430×860、320×568 两档证据，可查对应布局和浏览器脚本。后续动效证据保留触发零点与时标。已存在 `CampVerification`、合成及战斗验证入口，优先扩展现有入口。
- 本轮证据在 `game/Work_Local/CampWebSync/reports/ui-dynamic-review`。用 `capture-web.cjs` 产生网页序列与试玩夹具，用 Windows 开发包的 `-campVerify <输出目录> -campWebMotionFixtures <指定视口的网页夹具目录>` 跑同存档，再用 `build-report.cjs` 生成可播放的并排 HTML。浏览器连续录帧写实际采样时间，存档必须可由原规则验证和加载。对有可变状态的网页快照及时做深拷贝。
- 首轮代表用例包括合成兵、强化入场、出征仪式、营地巡防、建筑完成、普通升级、突破、开箱和城堡胜利。随改动选集。关卡结算灯光和宝箱卡数分别检查，确认动效退场后主按钮可用。营地巡防交战要看命中前后，资源有真实奖励事件才显示掉落。
- 项目指定用网页原资源、共用状态栏、数字单行、按钮文字居中、地图世界锚定。保留短屏首屏可以点击主操作的约定。
- 核对用户提供的网页截图时，同时记录浏览器 CSS 视口、DPR、实际游戏容器尺寸、滚动位置和存档阶段。桌面外壳、首次提示和滑动后的页面会触发不同布局。出现 Unity 偏移时，依次核对正式 DOM、生成的数据、运行时覆盖，按同一状态分别记录误差。现行约定与复现方式见仓库内 `game/tools/CampWebToolkit.md`。
- 对照战斗回放时，固定两端使用同一地形块、同一阵型版本及同一回放时间。Camp 网页会为森林选择地形变体，合成自己的回放时缺少 `formation: 3` 也会让 Unity 套用旧阵型距离。遇到整屏镜头与脚点偏移，先核对夹具数据，再改表现。
- 命中对照要采送给绘制函数的脚点，网页调试返回的基础脚点尚未加上受击偏移。战后整队要各验一次正常战后快照和缺少快照时从回放恢复的入口。快照可能省略阵型版本，表现仍需沿用本场回放版本。
- 对照全屏战报需实际打开、刷新同一战报，再点击仍应可用的底栏。网页的背景轻模糊在 Unity 复用开窗截图缓存，验证刷新后仍是同一缓存对象。自动验收同时读取结果 JSON 的失败列表，单凭进程退出码无法判定截图审计通过。
- 对照固定区和局部滚动时，先滚到可升级的卡，再点真实按钮，记录实际等级、滚动偏移，以及切页回来是否重置。只调用刷新函数无法验证升级入口。对照造兵到三选一时，从实际触发门槛前一步开始，避免首次教程的额外标题高度混入等高比较。
- 对照 CSS 宽度断点时，记录浏览器的游戏框 CSS 宽、Unity 逻辑画布尺寸和系统密度。安卓设备用密度换算 UI 宽度，实体像素适合核对成品截图。分别验证窄宽断点两侧、以及同一宽度在不同像素密度下的效果。
- 纯配乐更新先从正式 HTML 与脚本中确认只有背景曲数据改变，再对照场景实际播放的曲目。网页 AAC 与 Unity Vorbis 的文件散列自然不同，核对解码后的时长、声道和声音强弱曲线。网页用真实点击解锁，切换音乐设置并快进到循环末尾验证回卷。Unity 验证播放进度和切场景后旧音源退出。报告分开记录运行验证和音源试听。
- 仅新增分层素材和动态参考时，先确认 Git 中的正式 HTML、入口代码和客户端是否已经接入，再用新档检查实际首屏及素材请求。逐帧报告把设计参考标清楚。首次播放、跳过与完成落档若仍待开发，依新功能的改动边界确认后再接线。

## 历史 uGUI 生成流程

- 主线是正式网页 → 浏览器实际排版 → 共享 JSON → 可编辑 uGUI Prefab。Toolkit 可使用同一份取样输出 UXML 和 USS。已有 Toolkit 手调可拿实际运行结果和网页对照，确认通用后补回取样或生成规则。只读 UXML 和 USS 会漏掉运行时的短屏重排、动态节点、字体绑定和动效。
- 从真实入口打开每个有意义的状态，采父子层级、稳定节点名、相对位置、实际文字、字体、颜色和原图。额外检查 CSS 叠放顺序、滚动区和裁切。关闭按钮、徽章等需同时验证截图可见和实际可点。复杂渐变和阴影可以独立截取装饰层，文字、按钮、布局与业务状态保留成可编辑控件。
- 生成器按稳定节点名更新已有对象，保留序列化引用和按钮事件。样式比较上次生成值、当前编辑值和新采样值，保留手调，更新未手调的属性。连续生成两遍检查文件与对象 ID 稳定；用手调颜色、外部节点引用、持久按钮事件做回归。编辑器入口是 `Camp → Web UI → Regenerate editable Camp UI prefabs`。
- 真实按钮、滑动、合成和战斗接回原有 C#。记录同存档下的打开、操作、关闭、重复触发与关键帧，检查实际挂载的界面及是否重复修改状态。默认使用 uGUI 预制体版，设置中可切换到 UI Toolkit 版。经典 uGUI 保留为历史对照列。
- 桌面取样时关闭移动模拟，记录浏览器与游戏内容框尺寸，以及 Canvas 的布局与像素尺寸。`-ForgePrefabCompare` 使用桌面主样本和短窗，按游戏内容框取样，再复用固定 `Camp.exe` 复测。报告内嵌图片并记录实际渲染器、同存档校验和仍有差异的位置。顶部安全区独立对照 0 和 59 CSS 像素，核对顶部美术连续、控件和营地热区下移量。

- 桌面端的弹窗和顶栏取样统一减游戏框的屏幕原点。取静态图前等页面进场和列表错峰动画落位，保留真实动效序列。用实际构建从营地切到透明底的页面，检查运行时状态栏和底图只挂一层。编辑器预览保存进场景的营地底图可能盖住新的暖色背景，编辑器初始画面里看不出来。短窗基准可裁到网页外框之外，实际验收仍应点到 Unity 的关闭与出征按钮。

- 网页改为宽屏铺满后，分别核对互动区、顶底美术和安全区。主页面与出征过渡等特殊入口要使用同一套宽度换算。固定战斗场景的回归要实际滚动下半区，核对场景顶边位置不变、滚动区从场景底边开始。

- 交付表写有动效时，用实际页面逐帧确认目标元素和伪元素可见。出征按钮曾声明扫光动画，伪元素同时被别的样式隐藏。城堡比分有对局顶部和战败摘要两处，按各自实际触发和 CSS 可见状态验收。

- 同名网页节点重新生成时核对实际父节点，保留节点 ID、引用和手调样式。原 DOM 多了一层滚动容器时，旧父子关系和旧描边会挡住详情内容。实际点开后检查标题、图标、物资和主要按钮，再查关闭。

- 在 Android 模拟器加载网页存档做实时动效对照时，以设备时钟更新时间戳。记录实际到账或实际阶段切换，保留录屏时间，并检查恢复存档和安全区设置。

- 营地曾把巡防所、作战室和铁匠铺的整栋建筑存进每一帧。固定像素在切帧时落到不同压缩块上，导致屋身闪烁。旧版以网页绘制函数为源，导出固定主体和局部旗、烟、炉火裁片。该次实测纹理减少约 66%，APK 缩小 29.8 KiB。当前主干保留固定主体，程序驱动旗、烟和炉火。检查实际渲染网格、取图坐标和颜色，另用 MuMu 采样确认固定屋身像素稳定、四种局部效果都在变化。证据在 `game/Work_Local/UIFeedback/camp-local-ambient`、`game/Work_Local/CurrentRegression/mumu`。

## 应用图标

- 对照网页外壳与打包页面的图标链接，检查内嵌 favicon、Apple Touch Icon、manifest 和 manifest 里各尺寸图标的实际加载结果。缓存版本应覆盖 manifest 与子图标。Unity 对照各平台原图、编辑器构建绑定和成品启动器。Android 自适应前景与原图存在位移时，对齐像素核对，并看至少一种实际启动器裁切，再用交付遮罩复核图解释差异。尺寸和哈希只能辅助定位，边缘透明度与角色轮廓都需要验收。本轮证据见 `game/Work_Local/CampWebSync/reports/e53a3c8`。
